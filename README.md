# こつこつ日和

日々の「できた」を記録すると、相棒の犬が育っていくスマホ向けの習慣記録・ダイエット応援アプリです。

## 起動

ビルドや依存パッケージのインストールは不要です。Python 3 があれば、リポジトリ直下で次を実行します。

```sh
python3 -m http.server 4317 --bind 127.0.0.1 --directory dist
```

ブラウザで http://127.0.0.1:4317 を開いてください。

## 機能

- 運動・食事・ストレッチ・休息の記録
- 習慣の累計による犬の成長となつき度の増加
- 記録の間隔に応じた表情や、「なでる」への反応
- 朝・昼・午後・夕方・夜に合わせた、こむぎからの短い声かけ
- 部屋の下に常設した会話欄からLuna（gpt-6-luna）へ話しかけ、行動を報告・補足し、褒め言葉を吹き出しにも表示
- デイリークエスト、えらいポイント、日報と日ごとのグラフ
- 画面いっぱいのおへや、自動のおさんぽ・くんくん・ボール遊び・伏せ寝、「おいで」で呼び寄せ
- 画面下のメニューから記録・もようがえ・履歴を開き、記録後はこむぎのおへやへ戻る
- おへやの飾り付け、気分・体重の記録、JSONバックアップ

データはブラウザの localStorage（`kotokoto-wellness-v1`）に保存されます。端末・ブラウザ間の自動同期はありません。

## 次期機能の仕様

ログイン・クラウド保存・既存端末の記録移行は [ログインとクラウド保存の設計](docs/account-and-cloud-storage-design.md) を参照。Firebase AuthenticationとFirestoreを使う設計です。Terraformの追加基盤はGCPへ適用済みで、Googleログインもプロバイダー側で有効化しました。GoogleログインとUIDごとのクラウド保存を実装しました。初回ログイン後に記録の取り込みか新規開始を選びます。既存データはまだ移していません。退会機能は後続です。

[こむぎとの会話とえらいポイントの仕様](docs/komugi-daily-quests-spec.md)に、Lunaとの会話、行動ごとのデイリークエスト、ポイント、日報・グラフの合意事項をまとめています。会話からの行動候補・不足情報の聞き返し・クエスト・ポイント・日報・グラフを実装しています。配点や運動クエストの目標値は調整可能な初期設定です。

[GCPデプロイ計画](docs/gcp-deployment-plan.md)に、Terraformで管理するCloud Runへの移設、既存の記録の引き継ぎ、残る設定をまとめています。2026年10月18日に専用プロジェクト `kotokoto-biyori` へデプロイしました。ビルドはCloud Build、Cloud Runへの反映はTerraformです。現在はユーザーの希望に合わせ、[Cloud RunのURL](https://kotokoto-biyori-oidgpmqhiq-an.a.run.app)からログインなしで開けます。記録は各ブラウザ内に保存され、以前のURLからの記録の引き継ぎは未完了です。

[Terraformの運用手順](infra/terraform/README.md)に、実装済みのbootstrap・foundation・auth・data・app構成と、検証・ビルド・適用方法をまとめています。Cloud Run用の配信サーバーは `node server/index.mjs` で起動できます。

## こむぎの見た目

ユーザーが選んだ、クリーム色と淡いアプリコット色のポメラニアンです。子犬・育ちざかり・おとなの3段階と、普段・うれしい・寂しい・なでられたときの4表情を透過画像で表示します。記録の累計や日付に応じて画像を切り替え、「なでる」や記録時には寄ってくる動きを付けています。

`design/` に承認された試作と、組み込みの画像生成ツールで使用したプロンプトを保存しています。画像の行は成長順、列は普段・うれしい・寂しい・なでられたときの順です。

おへやでは、歩く・くんくん匂いをかぐ・ボールで遊ぶ・伏せてひと休みを、自分のペースで繰り返します。床を押す移動操作はありません。「あそぼ」でボールへ近づいて遊び、「おいで」や記録・「なでる」で手前へ近づきます。非表示のタブでは停止し、端末で動きを減らす設定をしている場合は自動行動と「あそぼ」の操作を止め、遊ぶボタンも無効になります。遊びの途中でも呼び寄せや一時停止を優先します。移動位置や一時停止は一時的な表示状態で、保存データの形式は変更していません。

部屋を引きで眺める全画面UIです。スマホでは縦長、横長の画面では横長の背景に切り替えます。初期表示は `#room`。右上の「…」メニューから `#today`・`#decorate`・`#records`・`#companion` を開きます。吹き出しからも `#companion` を開けます。スマホの操作パネルは下から、横幅900px以上では右側に表示します。

`dist/room-viewport.mjs` がVisual Viewportの高さ・上端・下端をまとめて扱い、ソフトキーボードが開いたときも部屋・犬・吹き出し・入力欄を同じ表示範囲に収めます。キーボード表示中はメニューと補助表示を一時的に隠して入力欄をコンパクトにし、特に狭い縦画面ではこむぎと吹き出しを横に並べます。入力欄のblurだけでは配置を戻さず、キーボードが閉じて高さが戻ったときに通常表示へ復帰します。ピンチズームはキーボードと区別し、記録の保存形式や手動の動き設定を変更しません。

背景は家具の輪郭や質感をデフォルメした、やわらかい手描きのイラスト風です。配置・日差し・広い床は初版から引き継ぎ、実写寄りの初版画像も比較用に残しています。生成プロンプトは `design/illustrated-room-backgrounds-v2.prompt.txt` に保存しています。

## こむぎのおしゃべり

部屋を開いて約12秒後、その後は4〜7分おきに、時間帯に合った言葉を16秒ほど表示します。たとえば朝は「会いに来てくれて、もううれしいな」、夕方は「ここまで過ごしたきみに、花まる！」。端末の時刻を使い、今日の記録や気分に合うひとことも混ざります。

こむぎは、小さな「できた」や休息を具体的に褒めます。記録した直後は、運動・食事・ストレッチ・休息それぞれに合う言葉を12秒ほど優先表示。「なでる」には「きみの手、やさしいね」と返します。休んだ日にも、自分のペースで過ごせるような、温かい言葉を使っています。

記録や「なでる」の反応を優先し、会話を入力中・送信中・履歴を広げている間、記録や設定のパネルを開いている間、タブが非表示の間は話しかけません。設定の「ときどき話しかける」で休められます。音や、アプリを閉じたときの通知はありません。

おしゃべりの設定と直近の声かけ時刻は、記録とは別の `kotokoto-companion-chat-v1` に保存します。記録の形式・バックアップ内容は変更していません。検証は `node --test test/companion-chat.test.mjs` で実行できます。

言葉は、こむぎの名前としっぽ付きの吹き出しに表示します。犬が歩いたり手前に近づいたりすると、吹き出しも頭のそばへついていきます。画面の端でははみ出さないように動かし、高さの低い横向き画面では犬の横に表示します。吹き出しを押すと、こむぎの育成状況を見ることができます。

行動の切り替え・呼び寄せによる中断・一時停止・動きを減らす設定は `node --test test/companion-motion.test.mjs test/companion-chat.test.mjs` で検証できます。


## こむぎへの報告とえらいポイント

部屋の下に会話欄を常設しています。「ねえ、こむぎ」のような雑談も、「ストレッチした」「間食を控えられた」のような報告も、同じ場所から送れます。返事はこむぎの頭のそばの吹き出しで伝え、下は入力欄と小さな達成表示にします。履歴は右上の「…」メニューから専用の履歴画面を開いて見返します。入力欄の上に履歴ボタンや見出しは置きません。返事は時間で消さず、長文はタップで続きを読み、最後に読み終わると普段の声かけへ戻ります。送信するとこむぎが手前へ寄り、画面に合わせて最大2.25倍に大きくなって、おすわりして返事をします。到着とAPIの応答の両方がそろってから返事を表示し、読み終わると元の位置・大きさへ戻ります。点数は吹き出しに出しません。「今日何をしたか」を毎回聞く導入や、報告用の別ダイアログはありません。履歴画面で直近30往復を見返せます。

右上の「…」→「設定」で、呼ばれたい名前を20文字まで登録できます。名前は `kotokoto-profile-v1` に保存し、次の新しい会話ではLunaへ呼び名として渡します。普段の声かけにも反映し、空欄で保存すると「きみ」に戻ります。記録と同じく端末・ブラウザごとの設定で、JSONバックアップにも含めます。

アップ中は専用の表情画像 `komugi-pomeranian-talk-v1.png` を使い、ときどきまばたきします。返事の表示時は文字数に応じて1.8〜7秒だけ口を開閉し、ページを進めると再び動きます。体のコマは固定し、顔だけを切り替え、穏やかな呼吸を添えます。返信待ちや読み待ちでは口を閉じます。`dist/companion-face.mjs` が表情の時間と停止を管理し、手動停止・非表示タブ・端末の「動きを減らす」設定に従います。画像を読み込めない場合は従来の画像を表示します。生成指示は `design/komugi-talk-v1.prompt.txt`。

会話欄ではEnter（スマホの改行・送信キー）で送信し、Shift+Enterでは改行します。日本語IMEの変換確定・Safariのcompositionend直後・キー長押しでは誤送信しないようにし、Enterのkeydownを出さないモバイルキーボードの改行入力にも対応します。

名前が未登録で部屋を開くと、こむぎが吹き出しで「なんて呼んだらいい？」と尋ねます。下の欄で名前を答えると端末に登録し、こむぎがお礼を返して普段の会話欄に戻ります。「あとで」を選べば未登録のまま会話できます。同じページ内で繰り返し質問せず、登録済みなら表示しません。`dist/name-intro.mjs` が導線を担当し、名前の質問・登録のためにOpenAIを呼び出したり、ポイントを加算したりしません。

Lunaは固定モデル `gpt-6-luna` のResponses APIとStructured Outputsで、返事と行動候補を返します。reasoning effortは `low` を明示します。実行した本人の行動だけが候補となり、予定・否定・他人の話・極端な食事制限は達成にしません。返事では点数や「えらいポイント」を告げません。AIの判定には誤りがあり得るため、記録には訂正ボタンを用意しています。

実行できた報告には、最初にその行動を具体的に褒めます。数字や時間が不足していても、褒め言葉を先にして必要な質問を一つだけ添えます。相づちや「教えてくれてありがとう」だけで確認へ進めないよう、体重測定・散歩・ストレッチの返答例もプロンプトへ含めています。雑談や単なる数値の補足には無理に褒め言葉を足さず、未確認の成果や継続は作りません。

日付・重複・保存・ポイント計算はアプリ側、消費カロリーの推定はLuna側です。候補に現在の発言の根拠があること、訂正先が存在することを検証します。本人の報告するカロリー・時間・体重は、現在の発言や既知の値で確認します。Lunaの推定カロリーは別フィールドと根拠を必須にし、本人の報告値と混ぜません。既存の行動か追加か曖昧な運動は保留し、同じ要求IDの再送は加点しません。補足・日付・時間の訂正は元の行動を更新します。

各クエストのボーナスは行動ごとに1日1回。運動のクエストは初回20kcalだけで、上位クエストを増やしません。運動の通常点は、その日の合計Kに対して `四捨五入(10 × (K / 100)^1.1)`。間食の同じ工夫を食事やセルフケアにも重ねて評価しません。情報待ちの運動のカロリーは確定済みの集計へ含めません。ストレッチは時間がなくても実施だけで固定ボーナスを受け取れます。

### 消費カロリーの初期ルール

2026-10-18のユーザーの補足に合わせ、消費カロリーはLunaが推定します。本人が把握している消費kcalがあればそれを優先し、それ以外は運動の種類・時間や回数・強さ・体重などから目安を返します。通常の強度を仮定できる場合はその前提を明記します。実施時間や体重そのものを推測で埋めません。必要な情報が足りなければ、こむぎとして一つずつ聞き返します。ユーザーに消費カロリーの計算を求めません。

応答では `kcal`（本人の値）と `estimatedKcal` / `estimateBasis`（Lunaの推定と根拠）を区別します。端末では推定値を `estimate: {source: 'luna', kcal, basis}` として保存し、日報にも「Lunaの推定」と根拠を表示します。同じ報告は再推定して毎回加算せず、元の値を保存して再利用します。時間・体重・条件が変わる訂正はLunaに推定し直してもらい、アプリは日合計とポイントを再計算します。訂正フォームだけで条件を変えた場合は、古い推定を外して「続きを話す」で再推定できます。日付だけの訂正は推定を維持します。

体重は「きろく」の表示と共通の `measurementRecords` から最新の保存値・記録日を取り、推定に使う参考データとしてLunaへ送ります。古い運動の会話で答えた値より保存された体重を優先し、記録がある項目を聞き直しません。記録がないときは、以前に計算用として答えた体重も再利用できます。送信時に保存データを読み直すため、更新・訂正した体重も次の新しい会話に反映します。計算用の回答や保存済み体重の参照だけで体重記録クエストを達成させません。ストレッチの固定ボーナスのためだけに時間や体重を尋ねません。本人が分からない場合は保留を残し、ほかの会話を続けられます。旧版で保存した固定式の推定がある場合は保持し、新たな推定を端末内の固定式で生成しません。

### 記録と育成の引き継ぎ

新しい行動・判定・要求ID・訂正履歴は `kotokoto-progress-v1`、会話は `kotokoto-komugi-conversation-v1`。従来の `kotokoto-wellness-v1` は保持します。壊れたデータや未知のバージョンを上書きせず、保存に失敗したら入力を残します。ブラウザで利用できる場合はWeb Locksで同じ端末の複数タブの更新を直列化し、古い判定で更新済みの数値を上書きしません。同期はこのブラウザ内だけです。

初回導入時の成長経験値となつき度を基準として記録し、昔の記録をポイントへ遡及換算しません。以後は5ポイントにつきなつき度1、1ポイントにつき成長経験値1を初期設定とし、従来の習慣による値との大きい方を表示します。関係と成長には獲得合計の過去最高値を使い、休んだ日や訂正で育った姿を取り上げません。レポートのポイント自体は訂正後の正しい合計です。既存の種・所持品とえらいポイントを同じ通貨にはしません。

体重・食事は実際に内容が保存されてから固定ボーナスを付けます。旧ボタンのストレッチ・食事の工夫・休息・体重記録も新しい日報につながります。JSONバックアップは従来のversion 1の項目を維持し、`progress` を追加します。会話履歴は含みません。従来の形式を読む処理は未知の追加項目を無視できるため互換性を保ちます。

「今日のえらい」でクエストと合計、「きろく」で日報・運動/固定ボーナスを色分けした14日分の棒グラフを見られます。日付を選んで過去の報告や訂正を確認でき、未記録の日と記録済みで0点の日を区別します。

### 接続と運用

APIは `POST /api/chat` と `GET /api/chat/session`。本番キーはGCP Secret Managerのバージョン参照のみです。キー本体をブラウザ、Git、Cloud Build、イメージ、Terraform stateへ含めません。ローカルでは安全な専用手順で承認済みの `.env.local` を用意した後、`node --env-file=.env.local server/index.mjs`。静的配信だけでは会話APIを利用できません。

OpenAIへは入力、直近最大8往復、端末日付・時刻・成長段階、判定に必要な最大18件の行動の要約を送ります。運動の推定には、登録済みの体重と対象の運動条件も送信します。入力や過去の会話に含めた情報も送信対象です。`store: false` はOpenAIのすべてのデータ保持がなくなるという意味ではありません。

最大入力600文字、会話履歴合計5000文字、出力上限2400トークン（構造化された行動候補を含む）、30秒タイムアウト。同一セッション毎分6回/1日30回、全体1日120回/同時2回。上限と5分の再送キャッシュはプロセス内で、再起動やスケールゼロからの復帰には引き継ぎません。厳密な課金額の上限ではありません。実行の再送はサーバーのキャッシュと端末に保存した要求IDの両方で確認します。

検証は `node --test test/*.test.mjs`。Cloud Buildでも同じ全テストを実行し、外部APIを使わず、計算・クエスト・再送・補足・訂正・移行・API境界と既存機能を確認します。`node test/preview-report.mjs` は外部通信を一切しない固定応答でのUI検証用です。回帰テスト用にCloud Buildのソースへ含めますが、Dockerイメージや公開アプリには含めません。

送信時の寄り表示は `companion-motion.mjs` の `approachConversation()` が担当します。通常の歩行・遊びを中断し、約1.25秒で手前へ、読み終わると約0.9秒で元の距離へ戻ります。縦画面は犬の上、横画面は犬の横へ吹き出しを配置。小さい高さでは返事を60文字以内のページに分けます。「動きを減らす」・手動のおやすみ・非表示タブでは移動のアニメーションを省き、設定や保存データは変更しません。返事が届かない場合は通常の距離へ戻し、入力を残します。

会話の記憶は、過去のオーナー情報サマリー（最大2,000トークン）と今日の全対話を使います。翌日の最初の会話で、未要約の過去日分をLunaでまとめ直して保存します。設定の「覚えていること」で確認・リセットできます。日付は日本時間です。詳しくはアカウント設計書の「日単位のオーナー記憶」を参照してください。
