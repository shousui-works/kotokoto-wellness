# 食事写真と摂取カロリー

会話欄の写真ボタンから食事を撮影・選択し、料理別の量と摂取カロリーの目安を確認・修正して保存する。既存の運動の消費カロリー、ポイント計算、保存済みの記録を維持する。

## 操作

1. ログイン後、会話欄の写真ボタンを押す。
2. 写真を1枚選び、必要なら「ご飯は小盛り」「半分残した」などを補足する。
3. Lunaが料理名・推定量・kcalと前提を返す。食事が写っていない、または料理や量が分からない場合は撮り直し・補足を案内し、保存しない。
4. 食べた分に合わせて料理名・量・kcalを修正する。料理名・量を変えた料理は古いkcalを空欄にし、修正した料理一覧で見積もり直すか、本人がkcalを入力する。料理の追加・除外も可能で、見積もり直しても除外した料理は対象に戻さない。
5. 食べた日・食事区分を選び、新しい食事として保存するか、同じ日の記録済み食事へ反映する。
6. 「この内容で記録する」で確定。推定だけでは食事やクエストを確定しない。

「今日のえらい」と日付別の記録に摂取カロリーの合計を表示する。合計は記録された食事だけで、1日の必要量や摂取目標ではない。未記録を0kcalとみなさない。食事の訂正から摂取カロリー・内容・日付を変更でき、元の推定と訂正履歴を保持する。会話によって食事内容そのものが変わった場合は、古いカロリーを流用せず未記録に戻す。

## 推定と保存

- 承認済み `gpt-6-luna` / reasoning `low` / Responses APIの画像入力とStructured Outputsを使用する。
- 写真では油・材料・器のサイズなどが分からないため、実測値として扱わない。一般的な量を仮定できる場合は、その前提を示す。根拠を持てない場合は推定せず必要な補足を一つ尋ねる。
- 料理は最大12品、1品0〜5000kcal、1食合計20000kcalまで。これらは異常入力を拒否するための上限で、推奨量ではない。
- 写真の元データは端末で長辺1280px・512KiB以下のJPEGへ変換し、カメラのメタデータを除く。入力ファイルは20MiB以下。サーバーでも形式・バイト数・寸法を確認し、外部画像URLを受け付けない。
- 写真自体はアプリの履歴・Firestore・localStorage・ログへ保存しない。圧縮した画像を解析時だけOpenAIへ送り、APIでは `store:false` を指定する。OpenAI側の取り扱いまで「保存なし」と保証する意味ではない。
- 確定した食事は既存の `meal_log` に追加の `intake` として保存する。`intake.kcal` は確定値、`source` は写真推定のままか本人の修正かを示し、`estimate` に元の料理別推定と前提を保持する。旧データにフィールドがなくても読み込める。
- 既存の `kcal` / `estimate` は運動用のまま維持し、摂取カロリーを運動の消費・運動ポイントへ合算しない。食事記録のボーナスは既存の1日1回だけ。
- 保存済みの食事に反映する操作では新しい行を増やさない。確定時は既存のアカウント別保存待ちキューへ、写真を含まない食事内容・元の推定ID・revisionを保存する。通信が途切れた場合や再読み込み後も同じ要求IDと内容で再送し、二重登録しない。未確認の保存がある間は別の内容の保存を止め、別アカウントには引き継がない。
- 写真推定は既存会話と共通の認証・利用枠・同時実行枠を使い、利用量も既存のchat集計に含める。画像・会話・推定本文は利用量ログへ出さない。

## 検証

`node --test test/*.test.mjs` は外部AIを使用しない。写真の入力境界、認証・UID分離、利用制限、同時実行、再送、保存前の非確定、訂正、旧記録の互換性、摂取と消費の分離を検証する。

自身によるレビュー後、量だけを変えたときの古いkcalの失効と修正量の再送、保存だけ完了して応答が届かない場合の再読み込み復旧、保存待ちデータに写真がなく別UIDで再送されないことも検証した。壊れた摂取記録の料理一覧は空配列へ変換せず、読み込みエラーとして元データを保護する。

`test/account-client.test.mjs` の保存応答喪失テストは、実際のアカウントAPIとメモリ内ストアで推定・食事保存まで実行してから、クライアントへの成功応答だけを破棄する。保存前のrevisionを持つ要求が再読み込み後に再送されても、食事・摂取カロリー・ポイント・サーバーrevisionが増えず、保存済みの内容を取得して保存待ちを解消することを確認する。Firestore実環境や外部AIの検証ではない。

`PORT=8104 MEAL_PHOTO_FIXTURE=food VOICE_FIXTURE=unsupported node test/preview-account.mjs` は実アカウントや外部AIを使わない画面確認用。返す料理とkcalは固定データで、実際の画像認識を検証するものではない。`MEAL_PHOTO_FIXTURE=not-food` で食事以外の案内も確認できる。

初回実装では、393×698と844×390の隔離ブラウザで、写真のJPEG変換、料理・量・kcalの修正、保存、通信断での下書き保持と復帰、保存後のカロリー・日付訂正を確認した。実APIは [University of Illinois Extensionの公開レシピ写真](https://eat-move-save.extension.illinois.edu/eat/recipes/brown-rice-sizzling-chicken-and-vegetables) で料理別の推定と前提の返却を確認した。写真のみと分量補足ありで値が変わることも確認しており、これは接続・動作の確認であって、一般的な推定精度を保証する検証ではない。実機カメラの操作は未確認。
