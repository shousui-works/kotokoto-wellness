# 文章の食事報告と摂取カロリー

「朝ごはんにご飯を茶碗一杯食べたよ」のような、実際に食べた内容の報告から、Lunaが摂取カロリーの目安を返して既存の食事記録へ保存する。写真は必要ない。写真の推定は従来どおり確認画面での確定を待つが、文章の報告は通常の会話の記録と同時に反映する。

## 量と根拠

料理と量が読み取れれば、毎回グラム数や全材料を聞かずに目安を置く。一般的な茶碗一杯や一人前を仮定した場合は、料理別の量と推定の根拠へ明記する。食べたと言われていない副菜や飲み物は追加しない。

「朝ごはんいっぱい食べた」のように料理が分からない場合や、「ご飯いっぱい」の量を置けない場合は、一度に一つだけ確認する。「一杯」と「たくさん」を決めつけない。推定できない食事は内容を残して情報待ちとし、0kcalとして合計しない。量の補足は元の記録へ反映する。

推定は既存の `gpt-6-luna` / reasoning `low` が担当し、端末側で食品別の固定計算を追加しない。目安の数値は会話欄の小さな記録結果と日報へ表示し、犬の返事で保存や処理の完了を先に宣言しない。

## 保存と訂正

- 候補の `mealIntake` は、`source`、`mealType`、料理別 `items`、`basis` を持つ。食事以外や推定できない場合はnull。
- 既存の `meal_log.intake` へ保存する。`source: text` は文章からの推定、`reported` は本人の明示した摂取kcal。既存の `photo` と `edited` を維持する。`origin` は、本人が後から修正しても元が文章・写真・申告のどれだったかを保持する。旧記録にoriginがなくても読み込める。
- 本人の申告値はその食事の現在の根拠文に実際のkcalがあることを確認する。運動の消費kcalを食事の申告値に流用しない。
- 料理は最大12品、1品0〜5000kcal、1食合計20000kcalまで。異常入力を拒否するための上限で、食べる量の推奨値ではない。
- 「ご飯は半分残した」などの量や料理の訂正では、元の料理別記録をLunaへ渡し、食べた分を再推定する。新しい食事を増やさず、元の値と根拠は訂正履歴へ残す。再推定できない内容変更は古いカロリーを失効させ、情報待ちに戻す。
- 日付・食事区分だけの訂正や言い換えでは、写真や本人の修正を含む確認済みkcalを再推定しない。通常の再送も既存の要求IDで重複を防ぐ。
- 摂取は運動の `kcal` / `estimate` と別。食事の量やカロリーを増やしても運動ポイントは増えず、食事記録のボーナスは従来の1日1回を保つ。

## 表示と確認

「今日のえらい」と日報には摂取合計、写真推定・会話推定・本人申告の件数を示す。各食事には推定元と前提を表示する。通常の訂正画面で摂取kcalを直せる。「今日の摂取カロリーは？」のツールも同じ保存値を集計し、文章の推定を写真からの推定として説明しない。

検証は外部AIなしの `node --test test/meal-text.test.mjs` と全テストで、入力境界、根拠、未推定と0、保存、補足、訂正、再送、旧写真記録、UID分離、摂取と消費の分離を確認する。
