# ぬいぐるみガチャと犬種図鑑の実装計画

2026年10月19日。承認されたぬいぐるみの見本を使い、えらいポイントでガチャを回し、集めるほど犬に詳しくなる機能を追加する。計画に続き、2026年10月19日に実装を進めた。実装内容と公開状況は末尾に記載する。

## 現在の対象

2026年10月20日の追加指定で、既存10犬種に20犬種を加え、犬30種類を有効にする。各1/30（約3.33%）の均等抽選。50ポイント/回、5ボタン交換、2段6枠の棚は維持。猫とうさぎは抽選・交換・図鑑・棚の表示から外したまま、過去の所持/取引の読込互換性を維持する。下記の初期8種類という記載は初回案の履歴。

## PRごとの収録範囲

PR #8は固定カタログ・承認見本・本計画のみ。抽選と保存はPR #9、UI・棚・配信用の個別画像はPR #10で追加する。末尾の実装内容は機能全体の記録であり、PR #8単独で利用できる機能を示すものではない。

## 合意した体験

- えらいポイントでぬいぐるみガチャを回す。ときどき自動でプレゼントされる方式にはしない。
- 犬種ごとに耳・鼻先・毛並み・体型が異なる、布の質感のあるぬいぐるみ。承認見本は `design/plush-collection/collection-concept-v1.png`。
- 入手したぬいぐるみを図鑑へ登録し、正式名称と説明から犬の知識を得る。部屋に棚を設け、集めた複数のぬいぐるみを並べて飾れる。
- 使用ポイントを理由になつき度・成長を下げない。既存の記録・日報・育成を保持する。
- 現金購入や課金ガチャは扱わない。こむぎは会話で点数を読み上げない。

## 初回の範囲と調整値

以下の数値・排出方式・交換比率は実装を進めるための初期案。合意済みの固定値として扱わず、初回実装前に仕様へ反映する。

| 項目 | 初期案 |
| --- | --- |
| ガチャ | 1回50ポイント、1回ずつ引く |
| 初回ラインアップ | 承認見本の犬6種、猫1種、うさぎ1種の計8種類 |
| 確率 | 全8種均等、各12.5%。種類と確率を引く前に表示 |
| レア度 | 初回は設定せず、種類を集める楽しさを中心にする |
| ダブり | 所持数を増やし、交換用ボタンを1個獲得 |
| 交換 | ボタン5個で現在のラインアップの未所持1種を選択 |
| 部屋 | 棚に複数体を並べる。初期案は2段×3枠の6体。枠数は画面で確認して調整 |
| コンプ後 | 図鑑の完成表示。再入手・所持数の増加は可能。ボタンは保持 |

50ポイントならストレッチの初回10ポイントだけでも5日で1回、1日20ポイントなら3日で最初の1回に届く。少しの行動でも続ければ回せる調整とする。未所持だけの抽選・天井・期間限定・10連は初回には追加しない。初回抽選を特別扱いしない。空の所持品からなら最初は必ず新規になる。

## 画面と操作

1. 部屋のメニューから「ぬいぐるみ」を開く。常設の入力欄や部屋の余白を圧迫しない。
2. 同じパネル内で「ガチャ」「図鑑」を切り替える。スマホは既存の下パネル、広い画面は右パネルを使う。
3. ガチャには使える残高、必要ポイント、現在の全ラインアップと確率を表示。「50ポイントで1回」を押すと送信中の重複操作を止める。
4. サーバーで入手・消費を確定してから箱が開く。短い演出後、ぬいぐるみ、正式名称、NEW／所持数、短い豆知識を表示。
5. 「図鑑を見る」「部屋に飾る」「とじる」を選べる。通信切断でも確定済みの結果は次の起動で回収する。
6. 「棚に飾る」で配置画面を開く。棚の枠をタップして所持品から選び、置く・入れ替える・しまうを操作する。ドラッグを必須にしない。同じ種類を複数置く場合は所持数の範囲内とする。部屋の飾った子をタップすると、その子の図鑑を開く。
7. 図鑑は番号順。未所持はシルエット、所持済みは画像と名称。詳細では正式名称、特徴や由来、豆知識、初入手日、所持数、資料リンクを見られる。
8. ボタン交換は別の確認表示で選択した種類と必要数を見せ、確定後に入手する。未所持がなければ交換を無効にする。

演出はスキップ可能。「動きを減らす」設定では静止した開封結果へ切り替える。結果は画面読み上げでも伝え、色や動きだけでNEWを示さない。ログインが必要な操作と圏外の閲覧を区別し、オフラインで消費・仮抽選しない。

## 正式名称と図鑑データ

`dist/plush-catalog.mjs` に版付きの固定カタログを作る。正式名称の基準をJKCに統一し、必要に応じFCIの標準も確認する。呼びやすい略称は補助表示に留め、図鑑の主見出しは確認済みの名称にする。

- 犬の項目は `breedId`、正式和名・英名、サイズ区分、毛の種類を分離する。単に「コーギー」「ダックス」とだけ登録せず、絵に対応した区分を決めてから名前と説明を確定する。
- プードルやダックスフンドのサイズ・毛種・毛色を、別々の犬種として誤って説明しない。後から同じ犬種の別ぬいぐるみを増やせるデータにする。
- 三毛は猫の犬種に相当する分類ではない。猫は動物種＋毛柄、うさぎは動物種として記載し、不明な品種を捏造しない。「犬種図鑑」と「ほかの動物」の分類を設ける。
- 説明は「ひとことで」「原産国・起源」「体の特徴」「もともとの役割」「豆知識」に分け、1項目の説明は合計200〜350字程度を目安にする。小さい画面では見出しごとに読みやすく配置。
- 性格は傾向と個体差を分ける。見た目だけで飼いやすさや性格を断定しない。説明に個人の健康情報を使わない。
- 各項目に `sources: [{url,title,checkedAt}]`、`contentVersion` を付ける。確認した事実を自分の言葉で短く説明し、画像や長文を転載しない。
- 図鑑本文、抽選、開封結果をLunaで生成しない。固定データと既存演出で実現し、ガチャによる追加API料金を発生させない。

資料の入口：
- JKC 犬種紹介 https://www.jkc.or.jp/breeds/
- JKC サイズ・毛色・毛種区分 https://www.jkc.or.jp/forms/breeds/
- FCI 犬種標準 https://www.fci.be/en/Nomenclature/

これらは調査先。個々の説明は各犬種の原典を実装時に確認してから公開する。

## ポイントと訂正の扱い

現在は `dist/progress.mjs` の `progressTotal` が訂正後の合計、`peakPoints` が育成に使う過去最高値を持つ。既存の `dist/model.mjs` の「たね」は別通貨。`peakPoints` や「たね」をガチャ残高に流用しない。

```text
獲得ポイント = サーバー正本の progressTotal(progress)
使用済みポイント = 確定したガチャ取引の消費合計
内部残高 = 獲得ポイント − 使用済みポイント
画面の利用可能残高 = max(0, 内部残高)
なつき度・成長 = 既存の peakPoints と基準値から計算（消費の影響なし）
```

既存利用者は現在保存されているえらいポイントをそのまま利用可能とする。古い「たね」や移行前の習慣へ新たな遡及加点はしない。

訂正で獲得ポイントが使用済み額を下回っても、ぬいぐるみ・なつき度は取り上げない。画面は残高0とし、新しい獲得で差分を埋めるまで追加抽選できない。内部の負数は消さず、同じ記録の削除・再追加で二重に使えないようにする。日報は消費前のその日に獲得したポイントを維持し、ガチャ消費は専用履歴へ分ける。

## サーバーと保存

- 新規 `dist/collection-model.mjs`：所持数・ボタン・棚の配置・残高表示の正規化。サーバーとクライアントで共有できる純粋な計算を分離。
- 新規 `server/plush-gacha.mjs`：有効カタログ、価格、均等抽選、ガチャ・交換の検証。抽選はサーバーの暗号学的乱数を使う。Lunaやクライアントへ結果決定を任せない。
- 既存 `/api/commands` のUID認証・要求ID・revisionと整合する操作を追加。`plush_draw`、`plush_exchange`、`plush_display` を想定。配置操作は枠IDとぬいぐるみID（しまう場合はnull）を指定し、枠の有効性・所持数・配置中の個数をサーバーで検証。入れ替えは一括確定し、同じ個体を別の枠に複製しない。入力は操作と要求ID等のみで、残高・抽選結果・確率・ボタン数は受け取らない。
- データは `users/{uid}` の配下へ保存。コレクション・財布・棚の配置はサーバー正本。配置は安定した棚ID・枠IDとぬいぐるみIDの対応として保持し、画面のピクセル座標は保存しない。初回読み込み時に既存アカウントへ空の所持品・消費0を補う。
- 財布・所持数・ボタン・初入手日・履歴をFirestore transactionで同時確定。通常の記録訂正とも同じアカウントrevisionで競合検出する。
- 抽選結果の候補は要求単位でサーバーが生成し、同じtransactionの自動再試行では再抽選しない。確定後の結果だけをクライアントへ返す。
- 長期保持する要求ID別の取引を作り、通常の一時的なoperationsが期限切れになっても、同じ要求の再送で再消費しない。同じIDで別内容なら拒否。結果・価格・catalogVersion・時刻を保存し、後の値上げやカタログ変更で過去を改変しない。
- 全取引を毎回アカウントへ詰めず、所持数は種類ごとの集計、使用額は集計値、履歴は要求ID別のドキュメントにする。履歴閲覧は件数制限とカーソル付き。
- 通信断では同じ要求IDで結果確認・再送。別端末の同時操作は二重消費を防ぎ、足りない残高では何も付与しない。
- UIDごとの読取キャッシュと保存データへ追加する。クライアントからのJSONバックアップや初回インポートで財布・取引・ぬいぐるみを増やせないよう、収集品の書込みをガチャ/交換だけに制限する。エクスポートはできるが、再インポートではサーバー所持品を上書きしない。
- 既存のFirestore全拒否Rules・サーバーIAMを継続。まず既存の名前付きDBで実装し、新しいGCPサービスやTerraformリソースは増やさない。必要な索引のみ検証して追加。

## 素材と部屋への配置

承認見本は方向性の確認用なので、文字・背景・台座を含む1枚絵をそのまま切り抜いて正式素材にしない。8体それぞれを独立した透過PNGとして制作し、色・大きさ・足元の基準・照明を統一する。カタログ一覧の縮小画像と部屋用の画像を用意し、圧縮後の容量を計測する。犬種/サイズ/毛種の資料確認後にシルエットを合わせる。

初回から部屋に棚を作り、複数のぬいぐるみを並べる。初期案は2段×3枠の6体。右奥の既存キャビネットを飾り棚として使い、既存家具の脚・外枠・床との接地を活かす。独立レイヤーの開いた棚とぬいぐるみを前板の内側へ重ね、窓の前へ別の大きな家具を置かない。背景のcover拡大・中央の切り抜きと同じ変換を使い、縦横の原画座標へ追従させる。背景画像へぬいぐるみを焼き込まない。

- 空の棚にも置き場所が分かる配置画面を用意。部屋での空き枠表示や編集操作は配置モードだけにし、通常の部屋は自然な見た目を保つ。
- 棚の枠ごとに足元を揃え、犬種の体型の違いを残しながら収まる大きさにする。長い体や耳が隣の子へ重ならない余白を取る。
- スマホ縦・横・広い画面で棚の位置とサイズを調整。犬の顔・歩行・吹き出し・入力欄を妨げず、キーボード表示中もレイアウトを保つ。必要なら既存の歩行可能範囲へ棚の領域を反映する。
- 所持品が増えても飾る順番は勝手に変えない。新しく引いた子を置くときは、既存の子を自動でしまわず、ユーザーが枠を選ぶ。
- 棚を増設できるデータ構造にする。初回の枠数と増設のタイミング/条件は調整事項とし、未合意のポイント消費や解放条件を追加しない。

犬がくわえる専用アニメーションや、一緒に寝る演出は後続とする。棚に並べる体験は初回リリースに含める。

## 受け入れ検証

- 50ポイントで1回、49以下では変化なし。累計育成・日報・「たね」は減らない。
- 再送、長期経過後の同一要求、ダブルタップ、2端末、transaction自動再試行、応答直前の切断で取引が1件になる。
- 抽選の境界と各種への割当を注入乱数で検証。大きな確率統計のテストではなく、均等な選択処理と公開カタログの一致を確認する。
- 初入手/ダブり/交換/全部所持/棚の配置・入れ替え・取り外しが正しく、ボタンの不正増加や他UIDの読取り・消費を拒否する。
- 訂正で残高が減る場合、訂正の取り消し、日跨ぎ、端末同期、旧アカウント・JSON取り込みでも既存データを保持する。
- 同じ種類の配置数が所持数を超えず、不正な枠ID・他人の所持品を拒否する。満杯でも新規入手でき、配置済みの子は自動で消えない。配置を別端末と再読込後も保持する。
- 履歴のページ分割とUID変更時のキャッシュ消去、未完了要求の回収を確認する。
- 全説明の原典、犬種名・サイズ/毛種・絵の一致、未発見のシルエットと入手後の解放を確認する。
- スマホ縦横、キーボード、拡大文字、読み上げ、動きを減らす設定、画像失敗・通信失敗で確認しスクリーンショットを残す。
- Nodeの関連/既存テスト、隔離した架空UIDの実Firestore検証を行う。実ユーザーのポイントや所持品をテスト変更せず、検証だけのAI通信もしない。

## 後続PR #9・#10の実装記録

以下は後続PRのブランチに存在する実装・素材の記録。PR #8には固定カタログのみを含み、以下の抽選・保存・UI・個別画像・検証スクリプトは含まれない。PR #8単独で利用・検証できる機能を示すものではない。

初回の数値は50ポイント/回、8種均等、ダブり1ボタン、5ボタン交換を採用。catalog/collection-model/plush-ui/plush.cssとserver/plush-gachaで実装。棚は2段6枠。飾ってある子を別の枠に選ぶと、その枠の子と入れ替える。未所持の犬種はシルエット、6犬種と2動物の説明と原典を固定カタログへ保存。各8体の透過素材は配信用に長辺384pxへ縮小し計約1.4MiB。

Firestoreは users/{uid}/collection/state に消費・所持品・配置・直近結果、users/{uid}/plushTransactions/{requestId} に取引を永続保存。既存の一時operationsにもIDを予約し、通常の記録と同じ要求IDを使い回せない。会話削除でoperationsが消去されても抽選の永続取引で再送を抑止する。履歴は20件ずつ、単一at索引とカーソルで取得。新規サービス/索引定義/Terraform構成の追加はない。

features/plushGacha.enabled=false を運用者が設定すると、新しい抽選と交換を停止する（未設定は有効）。過去の結果の再送・図鑑閲覧・配置は保持する。設定は一般ユーザーから書けない。旧イメージへの切り戻しでも独立したcollection/取引ドキュメントを上書きしない。
